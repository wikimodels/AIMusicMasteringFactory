## 0. Глобальная архитектура проекта

**ВНИМАНИЕ:** Мы работаем через пакетный менеджер `poetry`. Все скрипты запускаются строго из корня `AIMusicMasteringFactory` через команду `poetry run python scripts/название_скрипта.py`.

```text
AIMusicMasteringFactory/
├── sound/
│   ├── wav_input/          ← Сюда копируются сырые треки перед обработкой (только WAV)
│   ├── wav_output/         ← Сюда попадают готовые отмастеренные WAV (имена 1-в-1)
│   └── mp3_drops_output/   ← Сюда попадают 30с MP3-нарезки (Drops для сторисов/превью)
├── video/
│   ├── video_input_vertical/    ← Исходные вертикальные видео (Reels / TikTok / Shorts)
│   ├── video_input_horizontal/  ← Исходные горизонтальные видео (YouTube / VK)
│   ├── video_output_vertical/   ← Готовые обработанные вертикальные видео
│   └── video_output_horizontal/ ← Готовые обработанные горизонтальные видео
├── metadata/
│   └── <Album_Name>/       ← В этой подпапке хранятся TXT-тексты к песням и metakeys.json альбома
├── keywords/
│   ├── liminal_phonk.md        ← Глобальный банк SEO-запросов, тегов и лора
│   └── liminal_phonk_albums.md ← Список альбомов и их специфичные ключевые слова
└── scripts/
    ├── process_batch.py          ← Скрипт интеллектуального переименования (UUID -> Имя)
    ├── suno-mastering.py         ← Главный скрипт мастеринга на базе Librosa/FFmpeg
    ├── tag_wavs.py               ← Скрипт внедрения RIFF-тегов в готовые WAV-ки с помощью pytaglib
    ├── video_crop_vertical.py    ← Кроп + апскейл до 1080×1920 (вертикальные видео)
    └── video_crop_horizontal.py  ← Кроп + апскейл до 1920×1080 (горизонтальные видео)
```

## ШАГ 1. Подготовка и Очистка (Clean Stage)

Перед запуском любой новой партии треков (альбома), необходимо убедиться, что папки рабочих этапов пусты, чтобы треки не смешались.

**Правило:** НЕ ПЫТАЙСЯ удалить данные из `metadata/`. Там лежат сохранённые альбомы. Чистить нужно только рабочий конвейер:
- `sound/wav_input/`
- `sound/wav_output/`
- `sound/mp3_drops_output/`

**Действие:** Напиши короткий Python `os.remove` цикл прямо на лету (или вручную удали файлы из этих трех папок).

---

## ШАГ 2. Копирование сырья из источника (Ingestion Stage)

Исходные треки скачиваются из Suno AI (через браузер или загрузчик) в системную папку загрузок (например: `C:\Users\Vitali\Downloads\Liminal Phonk`). 

Файлы всегда поставляются парами, с длинным мусорным UUID-кодом в названии:
- Звук: `Liminal_Phonk-SongTargetName-d1a123bc-1111-2222...wav`
- Данные к звуку: `Liminal_Phonk-SongTargetName-d1a123bc-1111-2222...wav.txt` (содержит prompt, теги, лирику)

**Действие:**
Скопируй ВСЕ `*.wav` и `*.txt` файлы из исходной папки в рабочую транзитную папку: `sound/wav_input/`. 

---

## ШАГ 3. Анализ и Сборка Маппинга (Brain Stage)

Это самый важный этап человеко-машинного взаимодействия.

1. **Изучи контекст альбома.** Прочитай файл `keywords/liminal_phonk_albums.md`. Там описан лор, теги и концепция целевого альбома (например, *Level 0: Infinite Carpet*).
2. **Изучи сырьё.** Прочитай `.txt` файлы из `sound/wav_input/`. Посмотри на поле `Prompt` и `tags` у каждого файла. Так ты поймешь, какой у трека звук, вайб и настроение.
3. **Придумай имена.** На основе `keywords/liminal_phonk.md` сгенерируй SEO-оптимизированные названия. 
   - *Title (для метаданных)* пишется в Title Case. Предлоги со строчной буквы (если не первые).
   - *Filename (имя файла)* пишется через `_` (snake_case). Никаких спецсимволов (`'`, `!`, `/`, `?` вырезаются). 
   - **Уникальность!** Названия должны быть на 100% уникальны в рамках одного альбома, поэтому ОБЯЗАТЕЛЬНО сверяйся со списком файлов в `metadata/<Название_Альбома>/`, чтобы не перезаписать существующие чужие треки.

Когда таблица "UUID -> Title -> Идеальный Filename" готова — **ПРЕДОСТАВЬ ЕЁ НА АПРУВ В ЧАТ**.
Только после утверждения переходи к шагу 4.

## ШАГ 4. Переименование файлов (Renaming Stage)

Для этого шага используется скрипт `scripts/process_batch.py`.
Внутри скрипта в секции НАСТРОЙКИ нужно вручную поменять 2 переменные:
1. `ALBUM_NAME` = "Название_Твоей_Целевой_Папки"
2. `RENAME_MAP` = `{"твой-длинный-uuid-1": ("Title Name 1", "Title_Name_1"), ...}`

**Логика работы скрипта process_batch.py:**
- Он ищет `*uuid*` в папке `wav_input`.
- Находит `WAV`: переименовывает его внутри `wav_input/` из уродливого `Liminal..123.wav` в чистое `Title_Name_1.wav`.
- Находит `TXT`: меняет внутри него заголовок `Metadata for: ...` на новый, меняет строку `Title: ...` на новый Title. Затем перемещает этот `.txt` файл ИЗ `wav_input` В `metadata/<ALBUM_NAME>/`. 
- Защита от дублей: если в Метадате уже есть `.txt` с таким именем, скрипт добавит суффикс с датой (чтобы ничего не затерлось).

**Действие:** Запусти `poetry run python scripts/process_batch.py`.
**Результат:** В `sound/wav_input/` лежат только чистые красивенькие `.wav` треки. Все `.txt` файлы безвозвратно улетели в свои законные альбомы внутри `metadata/`.

## ШАГ 5. Формирование SEO-матрицы альбома (metakeys.json)

Никакой ручной прописки тегов через Windows Properties (это ломает кодировки и файлы). Все теги задаются централизованно через файл.

В папке `metadata/<ALBUM_NAME>/` создай файл `metakeys.json` по следующему шаблону.

```json
{
    "album": "Level 0: Infinite Carpet",
    "artist": "VRNOX",
    "year": "2026",
    "copyright": "2026 VRNOX",
    "genre": "Liminal Phonk; Trap; Dark Ambient; Lo-Fi; Atmospheric",
    "comment_template": "Liminal phonk. {TRACK_VIBE}. For focus, ADHD, sleep, backrooms aesthetic.",
    "keywords_ikey": "backrooms, liminal, phonk, trap, lo-fi",
    "track_vibes": {
        "Cave_Echo_Anemoia": "Suffocating cave echo, anemoia focus",
        "Твое_Имя_Без_Wav": "Здесь краткий vibe конкретно этого трека, он подставится в шаблон"
    }
}
```
**Важно:** 
1. Поле `genre` — должно писаться через `; ` (точку с запятой). Алгоритмы стримингов видят это как список тегов. 
2. Названия ключей внутри `track_vibes` должны математически строго совпадать с названиями будущих WAV файлов (без расширения).

## ШАГ 6. Аудио-Мастеринг (DSP Pipeline) 

Теперь работает тяжелая артиллерия. Скрипт `scripts/suno-mastering.py` берёт каждый файл из `sound/wav_input/` и прогоняет его через цепь:
1. High-Pass Filter (урезает бас ниже 30Гц).
2. Mid/Side эквализация (вычищает "сундучное" грязевое эхо нейросетей + делает ВЧ стерео-расширение).
3. Гармоническая сатурация (добавляет аналоговой "плёнки").
4. Динамический De-harshing (подавляет противные режущие 3-8кГц цифровые артефакты Suno, когда вокал орет).
5. TPDF Dither.
6. Выгоняет через FFmpeg под стандарт `EBU R128 (-14 LUFS)`.
7. Вырезает самый жирный дроп (30с) в MP3 и кидает в `sound/mp3_drops_output/`.
8. Рисует крутой аналитический график PNG в папку `analysis/`.

**Действие:** 
Запусти `poetry run python scripts/suno-mastering.py`

**Результат:** Готовые звуковые шедевры ложатся в `sound/wav_output/` один-в-один под теми же прекрасными чистыми именами, которые мы дали им на Шаге 4.

## ШАГ 7. Инъекция SEO Тегов (Metadata Injection)

Отмастеренные WAV-файлы — чистые холсты. Нам нужно вшить в их стандарт `RIFF INFO` все теги, чтобы Spotify, Apple, Google и YouTube Music могли их правильно проиндексировать. Инструмент `pytaglib` делает это нативно.

Скрипт `scripts/tag_wavs.py` открывает `sound/wav_output/`. Под каждый увиденный WAV он стучится в твой `metadata/<ALBUM_NAME>/metakeys.json`, берет оттуда Год, Артиста, Жанры, формирует Comment (сшивая Шаблон + Вайб трека), и сохраняет прямо в заголовок файла. 

**Действие:**
Открой `scripts/tag_wavs.py` и убедись, что переменная `ALBUM_NAME` там выставлена на правильный целевой альбом (тот, чей `metakeys.json` мы делали).  
Затем выполни: `poetry run python scripts/tag_wavs.py`

**Действие:**

В интерфейсе можно прослушать каждый трек, выделить галочками неудачные и нажать "Удалить". Файлы будут физически удалены с диска из папки `sound/mp3_drops_output/`.

### 11.2. Кроп + Апскейл до HD

Два отдельных скрипта для видео — по формату ориентации. Скрипты **не смешивают** папки: каждый читает свою `input`-папку и пишет в свою `output`-папку.

| Скрипт | Формат | Читает из | Пишет в | Целевое разрешение |
|---|---|---|---|---|
| `video_crop_vertical.py` | Reels / TikTok / Shorts | `video/video_input_vertical/` | `video/video_output_vertical/` | **1080×1920** |
| `video_crop_horizontal.py` | YouTube / VK / Twitch | `video/video_input_horizontal/` | `video/video_output_horizontal/` | **1920×1080** |

### Что делает скрипт (один проход FFmpeg):
1. **`ffprobe`** — определяет исходное разрешение видео.
2. **Crop** — срезает `CROP_PERCENT` (по умолчанию 4%) с каждой стороны. Убирает ватермарки, чёрные полосы, артефакты по краям.
3. **Scale + Lanczos** — растягивает обрезанный кадр до целевого HD-разрешения алгоритмом Lanczos (максимальная чёткость при апскейле).
4. **Кодирование** — H.264 (`libx264`), `preset slow` (или `veryslow`), `crf 18` (или `16` для максимального качества), `pix_fmt yuv420p` (совместимость).

---

### 11.3. Удаление звука из видео (Audio Remover)

Если нужно быстро вырезать аудио-дорожку из видео без ухудшения качества самой картинки, используй скрипт `scripts/remove_audio.py`.

Папки для работы:
- **Читает из**: `video/video_with_sound/`
- **Пишет в**: `video/video_no_sound/`

**Действие:**
Закинь видео в `video_with_sound` и запусти:
```bash
poetry run python scripts/remove_audio.py
```
Скрипт применяет команду `-c:v copy -an` (удаляет все аудиоканалы), поэтому процесс происходит мгновенно, без пережатия (lossless). Бот пришлёт уведомление по итогу.
5. **Звук** — управляется флагом `KEEP_AUDIO`.

### Параметры в секции НАСТРОЙКИ (менять только там):

```python
CROP_PERCENT = 0.04   # Сколько % срезать с каждой стороны (4% по умолчанию)
KEEP_AUDIO   = False  # False → немое видео (для наложения трека), True → сохранить оригинальный звук
TARGET_W     = 1080   # Ширина целевого разрешения
TARGET_H     = 1920   # Высота целевого разрешения
```

### Запуск:

```bash
# Вертикальные видео (Reels / TikTok / Shorts)
poetry run python scripts/video_crop_vertical.py

# Горизонтальные видео (YouTube / VK)
poetry run python scripts/video_crop_horizontal.py
```

### Пример вывода в консоли:
```

Целевое разрешение: 1080×1920  |  Кроп: 4% с каждой стороны  |  Звук: удаляется
------------------------------------------------------------
[1/2] 🎬 Рендер: my_clip.mp4
         Исходник: 1080×1920  →  Кроп: 992×1766  →  Финал: 1080×1920  [🔇 немое]
```

## Эпилог: Антипаттерны (НЕ ДЕЛАТЬ!)

- ❌ Не писать теги в Windows Properties мышкой (ломает битовку WAV и затирает ID3). Только `pytaglib` через скрипт `tag_wavs.py`.
- ❌ Не использовать `mutagen` или "встройку" в `ffmpeg` для записи жанра и ключевых слов в WAV (они не умеют нормально писать RIFF INFO чанки, теги теряются).
- ❌ Не оставлять в названиях файлов спецсимволы.
- ❌ Не запускать PowerShell-скрипты на переименование и перемещение. Избегай их. Слишком много проблем с пробелами/кодировками. Python-скрипты в папке `scripts/` уже решают все проблемы.
- ❌ Не класть вертикальные видео в папку `video_input_horizontal/` and наоборот — скрипты работают строго со своей папкой.
